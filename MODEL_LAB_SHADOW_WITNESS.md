# CASH Model Lab: public shadow observation (research only)

## Evidence boundaries

The Model Lab shadow momentum candidate is **not calibrated**. Its public spot input is **not** the Kalshi BRTI reference, and neither the shadow journal hash chain nor the source-side forecast timestamp proves an independent prediction timestamp.

The service exposes an isolated GET /api/model-lab/shadow/export only when an existing absolute audit directory (CASH_AUDIT_DIR) is mounted. Without durable storage this returns HTTP 503 and shadow collection remains OFF. GET /api/model-lab/shadow/status always publishes safe high-level diagnostics.

When enabled, the service appends **one** shadow forecast per exact KXBTC15M contract ID, after verifying a public Kalshi target, contract rules, fresh single-source Kraken/Coinbase history, and a 90-to-780-second horizon. The new hash-chain snapshot is fsynced to the audit volume **before** the public API makes it visible. A corrupt prior snapshot blocks startup instead of resetting history. The existing early/late models and settlement archives are unchanged.

## Separate GitHub runner capture

The GitHub workflow at .github/workflows/shadow-public-observer.yml runs on the default branch with a 5-minute requested schedule (not a guaranteed exact cadence). Its runner fetches the full public snapshot, checks the entire chain, and **then** records its independent runner time. On November 18 the configured five-minute cron was actually delivered much less frequently, leaving 9 of 12 source-committed forecasts without a matching pre-expiry external witness, including one directional source-only claim. These source-only decisions must NOT be retroactively witnessed or counted in accuracy. The read-only `cash-shadow-source-coverage-runner.js` now compares full hash-verified source commitments against unique GitHub-witnessed contracts, separates expired/open source-only records, and stores the gap count in its own diagnostic artifact. Three additional **opportunistic** triggers can invoke the same witness routine when a trusted `main` branch **scheduled** run of the dual-model snapshot, pre-expiry research observer or settlement reconciliation completes successfully. All witness branch writes are serialized and use the same runner-clock check. These extra runs improve chances but never guarantee continuous observation or a five-minute interval, and may consume additional GitHub Actions minutes. **Bounded witness retry:** A scheduled or trusted scheduled-workflow-triggered shadow capture now makes an initial GitHub-runner fetch and, only if it finds no eligible pre-expiry record (or source unavailable), retries at up to 30-second intervals for up to three minutes from runner start. A successful observation exits immediately and is never overwritten by another attempt. Each attempt uses a fresh runner UTC timestamp captured AFTER the response. The last attempt is the only one archived in the existing immutable one-file-per-run format; unsuccessful interim attempts are *not* invented as witnesses. The PR smoke runs without this multi-minute wait. This expands a single scheduled observer's opportunity window but cannot recover predictions missed before the runner started, guarantee every contract is seen, or overcome GitHub cron delays. It increases Actions run duration and consumes additional runner minutes whenever a contract is not immediately eligible. It only retains records more than 15 seconds before the advertised close. GitHub Actions can be delayed; empty observations must never become qualified forecasts.

Each run uploads a 90-day artifact, even if the source is down, and adds eligible pre-expiry source-claim observations to the separate public cash-shadow-public-witness Git branch, one immutable file per Actions run. The branch is distinct from existing research/archive/settlement branches.

**Additional direct public exchange comparison (new):** After the original runner timestamp is captured and before the witness branch commit, the same trusted GitHub runner retrieves the current public Model Lab journal again, verifies its whole hash chain and finds each originally observed frozen event by exact hash, then issues read-only direct Kalshi public market GETs for up to 12 eligible contracts. Its second independent runner reception timestamp must still be more than 15 seconds before published close, and the public contract must be active/unresolved with matching ticker, closing time, `greater_or_equal` rule and floor strike in cents. Missing, late, or contradictory API reads remain UNCORROBORATED. A separate `witness/shadow-exchange-check.json` diagnostic is uploaded as a 90-day GitHub artifact. When the original preclose witness is eligible, both evidence files are appended in the same commit to separate `public-shadow-witness/` and `public-shadow-exchange-checks/` directories of the existing append-only witness branch. Older witness entries intentionally remain valid without secondary records. This is a limited comparison of two public sources at observation time, **not independent authentication of the BRTI index or proof of a correct trading prediction**; it has no effect on settlement grading or trading permissions.

Public witnessing attests only that GitHub's runner observed the claimed commitment before expiry. It does not establish model inference time, source truth, BRTI settlement, contract completeness, calibrated performance, actual fills, or real-money eligibility. The independent qualification count is always zero and real-money orders remain disabled.

## Staging rollout and checks

1. Review all PR CI, including witnessed-settlement reconciliation.
2. Mount persistent Railway storage at /data on the existing CASH service and set CASH_AUDIT_DIR=/data in the same environment. This may incur Railway volume charges.
3. Deploy the merged GitHub main branch to the existing staging service.
4. Check /health, /api/model-lab/shadow/status, then the export. A valid, empty journal is initially expected. If the status shows unverified contract or insufficient history, do not invent forecasts.
5. Inspect the first scheduled GitHub witness artifact. Confirm source hash, runner observation time, actual eligible count, and zero qualification. Check the public branch for an appended record only if observed records exist.

No exchange orders or promotion to frozen CASH predictions are part of this change. Live model edge requires a separate, independently settled, chronological holdout experiment and explicit approval for any trading action.

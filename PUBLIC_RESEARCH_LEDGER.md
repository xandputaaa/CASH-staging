# CASH: public, monotonic evidence ledger

## Purpose

The live research service is a volatile Railway process with a ~160-market default late checkpoint capacity and no persistent volume. Existing GitHub Actions ZIPs expire after 30 days. The ledger is a **longer-lived copy of limited public evidence only**, NOT a replica of the licensed market index, an exchange's certified source of truth, or independently qualified win-rate data. It exists solely to preserve research observations in ordinary versioned Git history until a trusted long-term research store can be reviewed.

The new workflow \`.github/workflows/public-evidence-ledger.yml\` uses GitHub's \`workflow_run\` trigger **only when the already-existing "CASH witnessed-settlement reconciliation" workflow completed successfully from its scheduled job on the main branch**. It does not execute code from a pull request. Pull-request and manual observer runs are excluded from the persistent longitudinal ledger to avoid giving selectively timed tests the same provenance as an actual scheduled observation.

For each scheduled pre-expiry witness, the trusted default-branch validator:

1. Downloads the exact successful **scheduled** reconciliation artifact by its GitHub run ID.
2. Checks the reconciler's research-only/no-order/no-independent-certification flags and the witness source's schedule event, workflow GitHub-run creation time, source commit SHA, and pre-expiry runner time.
3. Whitelists only public KXBTC15M market IDs, model keys, original frozen YES/NO/WAIT, close time, SHA-256 of the frozen public research FORECAST event, GH observation IDs/timestamps, whether a separate direct public Kalshi preclose read matched, and future confirmed two-read final public source hashes/winners. Hypothetical one-contract public ask/fee sensitivity is clearly labeled unfilled and unprofitable for some correct calls.
4. Writes each distinct model/market file to a dedicated repository branch **\`cash-public-evidence-ledger\`**, under \`public-evidence/YYYY-MM-DD/MARKET_ID/late-v1.json\` (or \`early-v3.json\`). Original market ID, side, expiry and prediction hash are locked by code; contradictory later evidence causes a job failure rather than overwriting history.
5. Permits only additive scheduled observations for the same frozen commitment, or a previously missing independently re-read **public exchange payout** to be attached to an already-witnessed forecast. Before writing any file, all proposed changes are validated. Git commits preserve revisions; the workflow never force-pushes, deletes files, or modifies \`main\`.

**Privacy:** The repository and ledger branch are public. No user data, private API keys, exchange account balance, order history, CF Benchmarks licensed BRTI values, raw internal model feature histories, or other private payloads are copied. The archiver uses a strict whitelist and refuses unknown model sources or invalid contract IDs.

**Workflow security:** The \`workflow_run\` trigger has **GitHub repository write permission** and therefore needs extra care: its code is loaded only from the trusted default branch. The job's \`if\` requires a successful **scheduled** upstream run from the same repo's main branch; it never checks out a pull-request ref, executes any downloaded artifact as a script, or accepts filenames from the artifact as filesystem destinations. Instead it parses a known JSON file from a successful scheduled run and sanitizes every ID/timestamp/field. The only permitted push target is the dedicated ledger branch. GitHub's security documentation warns that a privileged \`workflow_run\` can become dangerous if PR source code or untrusted artifacts are executed. Branch writers or repository administrators can still rewrite/delete Git history; the ledger **is not an independent cryptographic notary**.

**Cost and reliability:** The new action is triggered at most once per successful scheduled 4-hour reconciliation; it uses standard GitHub-hosted Linux Actions and the existing built-in GITHUB_TOKEN, no new paid providers or account keys. GitHub token write permission is requested only by this new archival workflow; all existing observers, model collectors and settlement verifiers remain read-only. Repository permission policies may prevent the action from pushing; **do not claim a durable archive exists until the first archive commit is verified on \`cash-public-evidence-ledger\`**. Schedules can still be delayed or skipped, source ZIPs expire, network/API failures are possible, and the Railway journal can be lost before a reconciliation. Thus the ledger improves durability but **does not create complete chronological pre-expiry coverage**.

All research stats remain \`independentQualification:0\`, \`ordersEnabled:false\`, \`actualFillConfirmed:false\`. A GH runner clock, public Kalshi API result, and SHA digest cannot prove that the source service was honest when originally producing its frozen prediction; licensed BRTI input history and real exchange order execution are not independently audited. A valid prospective high-accuracy strategy and positive expected value remain unproven.

## Operational checks

Use GitHub Actions to examine the first **scheduled** post-merge reconciliation and the subsequent \`CASH public research evidence ledger\` workflow. Verify the workflow was not skipped, its \`CASH_LEDGER_PUBLIC_SCHEDULED_WITNESSES\` count is sourced from scheduled observer runs, and the resulting dedicated branch contains only the expected public JSON fields. Check the Git commit SHA, any rejected conflicting winner, and whether the action used a write-enabled GitHub token from the existing repo settings.

A ledger branch created in GitHub is not a promise that automation can write to it. If a scheduled job fails with GitHub token permissions or branch protection, keep the working read-only research collector and report the failure rather than bypass security policy or inserting personal credentials. The original Railway process must remain untouched while those permission questions are resolved.


## Complete ledger integrity check (November 17, 2026 update)

A read-only \`public-ledger-inspection.js\` now checks the **entire** dedicated ledger tree before and after each proposed privileged write. It rejects unexpected files, symlinks, oversized JSON, unknown/private fields, altered frozen model/market/side/hash/expiry, after-close or nonscheduled witness origins, inconsistent public payout evidence, or any hint of actual order execution or qualification. The archival workflow fails without pushing new public records if existing files fail structural validation.

A separate pull-request reconciliation step runs the same inspection against the **real sanitized output** of \`public-evidence-ledger.js\` with no branch writes or privileged token. Counters distinguish scheduled early and late witnesses, WAIT vs directional, two-read direct public settlement results, observed hits vs misses, and correct predictions with non-positive conservative *hypothetical* net after fee assumptions. Counters are **not** independently qualified trading performance.

This is a schema/provenance consistency check, not cryptographic notarization or proof that an already-committed Git ledger was never changed by a trusted repository writer. Its first fully automatic scheduled-run archive commit still needs to be verified separately. Until then, the ledger branch may contain just its initialization README. The Railway in-memory forecast collector is unaffected, and real orders remain disabled.


## Scheduled archival latency and operational visibility (November 17, 2026)

GitHub scheduled reconciliation previously ran only at minute 21 every **four** hours. A delayed or skipped job could leave fresh externally witnessed predictions unarchived for hours even when the GitHub observer had already captured them. The reconciliation is now *configured* to run **hourly at UTC :21**. It remains read-only and uses the same bounded public API checks, source-whitelisted GH witness artifacts, six-to-nine-minute runner budget, schedule-only archival trigger and no licensed/private exchange data. If repository status or Actions billing rules change, reduce frequency rather than silently accepting paid usage. **GitHub cron remains best-effort and can be delayed or skipped**; schedule frequency is not a guarantee of timely evidence commits.

The existing twice-hourly public journal backup also performs an optional **read-only** GitHub operational health inspection after safely uploading the research backup. \`ledger-archive-health.js\` examines recent scheduled reconciliation workflow runs, recent ledger workflow runs, and the head commit of the dedicated \`cash-public-evidence-ledger\` branch. It distinguishes no scheduled run observed, scheduled failure, scheduled reconciliation succeeded but ledger not confirmed, and an exact public archive commit whose Git message contains a run ID matching a successful scheduled reconciliation in the recent bounded window. This is operational corroboration—not an independent cryptographic attestation or proof that private model inputs were historical.

The backup job's health-inspection phase is deliberately **nonblocking**: if GitHub's public API is unavailable, it prints \`CASH_LEDGER_HEALTH_INDETERMINATE\` without invalidating the earlier SHA-verified forecast snapshot. It has no privileged write permissions, does not touch CASH's deployed forecast model, does not issue orders, and always reports independently qualified 0/100.

**First live scheduled archive commit remains a separate acceptance gate.** A healthy source run and a correct Git message are not sufficient if no actual public-evidence files were committed; manually verify the first scheduled \`CASH public research evidence ledger\` workflow result, Git branch commit, and sanitized contents. No real-money orders, fees, calibrated probabilities, guaranteed returns or independent qualifications are authorized.


## Repeated Kalshi verification reads are NOT mutable settlement fields (November 18, 2026)

The first **real automated scheduled archive succeeded** on GitHub Action run \`44251173616\` after successful scheduled public reconciliation \`44251036554\`. It committed **10 sanitized forecast evidence records**, including **3** directly reverified directional hits and **7** WAIT records, to \`cash-public-evidence-ledger\`. This verified the intended short-lived GitHub repository token was sufficient to create a Git commit and that the schedule-only guard correctly excluded **16** PR/manual observations from that archive run. No actual fills or independent accuracy certification was established.

Four subsequent scheduled archive runs (\`44268221168\`, \`44285422661\`, \`44302549200\`, \`44316155297\`) failed closed with \`Official final public settlement conflict: manual audit required\` even though their upstream scheduled public Kalshi reconciliations passed. Root-cause inspection of the **actual archived and later GitHub research reports** showed that the final public **winner and selected source evidence SHA-256 digests remained identical**, but the direct Kalshi second-read *elapsed time* had naturally changed between external GitHub audits (for example **21,283ms** in the original archive and **21,253ms** later). The old merge rule mistakenly treated this run-specific observation interval as immutable market settlement data.

The archive reconciliation now compares and locks the **actual immutable fields**—official winner, direct public market evidence SHA-256, CASH historical public journal evidence SHA-256, and two-read verification status—while explicitly excluding the new runner's read-spacing interval and GitHub reconciliation run ID from the equality check. Both old and new read-spacing values must independently be finite and at least **20,000ms**, or the proposed update fails closed. The archived original two-read interval, original GH run provenance, original frozen forecast event hash, and original public ask/fee economics are preserved without rewriting. Any changed official winner, source digest, historical forecast hash, or original paper quote still raises a conflict and aborts the entire Git commit. A late result can still be appended to a previously unresolved forecast and a genuinely new scheduled witness can still be added as another observation.

Regression tests reproduce actual observed **21,283ms vs 21,253ms** timing, no-op replay, new scheduled preclose witness addition, and refusal of altered winners, digest hashes, and invalid shorter-than-20s reads. This is a precision fix, not a relaxation of settlement verification or an excuse to override true conflicting market outcomes. The first subsequent **scheduled** archive success after deployment must be checked separately.

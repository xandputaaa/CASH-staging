# CASH: public, monotonic evidence ledger

## Purpose

The live research service is a volatile Railway process with a ~160-market default late checkpoint capacity and no persistent volume. Existing GitHub Actions ZIPs expire after 30 days. The ledger is a **longer-lived copy of limited public evidence only**, NOT a replica of the licensed market index, an exchange's certified source of truth, or independently qualified win-rate data. It exists solely to preserve research observations in ordinary versioned Git history until a trusted long-term research store can be reviewed.

The new workflow \`.github/workflows/public-evidence-ledger.yml\` uses GitHub's \`workflow_run\` trigger **only when the already-existing "CASH witnessed-settlement reconciliation" workflow completed successfully from its scheduled job on the main branch**. It does not execute code from a pull request. Pull-request and manual observer runs are excluded from the persistent longitudinal ledger to avoid giving selectively timed tests the same provenance as an actual scheduled observation.

For each scheduled pre-expiry witness, the trusted default-branch validator:

1. Downloads the exact successful **scheduled** reconciliation artifact by its GitHub run ID.
2. Checks the reconciler's research-only/no-order/no-independent-certification flags and the witness source's schedule event, workflow GitHub-run creation time, source commit SHA, and pre-expiry runner time.
3. Whitelists only public KXBTC15M market IDs, model keys, original frozen YES/NO/WAIT, close time, SHA-256 of the frozen public research FORECAST event, GH observation IDs/timestamps, whether a separate direct public Kalshi preclose read matched, and future confirmed two-read final public source hashes/winners. Hypothetical one-contract public ask/fee sensitivity is clearly labeled unfilled and unprofitable for some correct calls.
4. Writes each distinct model/market file to a dedicated repository branch **\`cash-public-evidence-ledger\`**, under \`public-evidence/YYYY-MM-DD/MARKET_ID/late-v1.json\` (or \`early-v3.json\`). Original market ID, side, expiry and prediction hash are locked by code; contradictory later evidence causes a job failure rather than overwriting history.
5. Permits only additive scheduled observations for the same frozen commitment, or a previously missing independently re-read **public exchange payout** to be attached to an already-witnessed forecast. Before writing any file, all proposed changes are validated. Git commits preserve revisions; the workflow never force-pushes, deletes files, or modifies \`main\`.

**Privacy:** The repository and ledger branch are public. No user data, private API keys, exchange account balance, order history, CF Benchmarks licensed BRTI values, raw internal model feature histories, or other private payloads are copied. The archiver uses a strict whitelist and refuses unknown model sources or invalid contract IDs.

**Workflow security:** The \`workflow_run\` trigger has **GitHub repository write permission** and therefore needs extra care: its code is loaded only from the trusted default branch. The job's \`if\` requires a successful **scheduled** upstream run from the same repo's main branch; it never checks out a pull-request ref, executes any downloaded artifact as a script, or accepts filenames from the artifact as filesystem destinations. Instead it parses a known JSON file from a successful scheduled run and sanitizes every ID/timestamp/field. The only permitted push target is the dedicated ledger branch. GitHub's security documentation warns that a privileged \`workflow_run\` can become dangerous if PR source code or untrusted artifacts are executed. Branch writers or repository administrators can still rewrite/delete Git history; the ledger **is not an independent cryptographic notary**.

**Cost and reliability:** The new action is triggered at most once per successful scheduled 4-hour reconciliation; it uses standard GitHub-hosted Linux Actions and the existing built-in GITHUB_TOKEN, no new paid providers or account keys. GitHub token write permission is requested only by this new archival workflow; all existing observers, model collectors and settlement verifiers remain read-only. Repository permission policies may prevent the action from pushing; **do not claim a durable archive exists until the first archive commit is verified on \`cash-public-evidence-ledger\`**. Schedules can still be delayed or skipped, source ZIPs expire, network/API failures are possible, and the Railway journal can be lost before a reconciliation. Thus the ledger improves durability but **does not create complete chronological pre-expiry coverage**.

All research stats remain \`independentQualification:0\`, \`ordersEnabled:false\`, \`actualFillConfirmed:false\`. A GH runner clock, public Kalshi API result, and SHA digest cannot prove that the source service was honest when originally producing its frozen prediction; licensed BRTI input history and real exchange order execution are not independently audited. A valid prospective high-accuracy strategy and positive expected value remain unproven.

## Operational checks

Use GitHub Actions to examine the first **scheduled** post-merge reconciliation and the subsequent \`CASH public research evidence ledger\` workflow. Verify the workflow was not skipped, its \`CASH_LEDGER_PUBLIC_SCHEDULED_WITNESSES\` count is sourced from scheduled observer runs, and the resulting dedicated branch contains only the expected public JSON fields. Check the Git commit SHA, any rejected conflicting winner, and whether the action used a write-enabled GitHub token from the existing repo settings.

A ledger branch created in GitHub is not a promise that automation can write to it. If a scheduled job fails with GitHub token permissions or branch protection, keep the working read-only research collector and report the failure rather than bypass security policy or inserting personal credentials. The original Railway process must remain untouched while those permission questions are resolved.
